## 可核验的作品集数字（本次验证快照）

- 13 个 Agent 业务/知识工具，其中 5 个写操作进入人工确认状态机；
- 16 个 DeepSeek 在线契约评测用例通过，含正常、越权、敏感信息、幻觉与多模态边界；这是特定评测集结果，不是模型“准确率”；
- 后端 42 个自动化测试、前端 8 个自动化测试通过；
- MySQL、Redis、后端与前端 4 个最终容器镜像在本次 Docker Scout 扫描中均为 0 Critical / 0 High；这不是“零漏洞”证明，NVD 全量依赖扫描仍受外部数据下载限制；
- 6 个 WorkBuddy 只读 MCP 工具通过协议冒烟，写操作不会通过 MCP 绕过确认。

数字必须和仓库最新 `docs/VALIDATION_REPORT.md`、评测 JSON 及 CI/本地日志一起使用；后续改代码后应重新运行，不能长期照抄。

## 可用于简历的真实表述

> 独立将 Java/Vue 智慧养老管理系统升级为可执行 AI Agent：设计 13 个真实业务/知识工具及 5 个写操作人工确认闭环，接入 DeepSeek/豆包可替换模型、RAG 引用、结构化输出与 WorkBuddy MCP；建立 Prompt 版本、限流缓存、PII 保护、运行观测和评测体系，并完成 Docker 化与前后端自动化回归。

建议在简历项目链接旁补充一行可复验结果：

> 本地验证快照：DeepSeek 契约评测 16/16、后端测试 42/42、前端测试 8/8；详细口径与限制见仓库验证报告。

不得追加“服务多少老人/机构”“提升多少转化”“创造多少营收”“已生产上线”等未经验证的结果。若面试官追问商业价值，应回答这是可运行个人作品与模拟解决方案，并展示验证方法，而不是编造客户案例。

## 求职前最值得补齐的三类证据

1. **真实业务接触**：争取一次可授权记录的机构访谈、校园实验室试用或企业实习，沉淀问题清单、决策过程和反馈；没有获得授权时只做匿名汇总。
2. **运营实验能力**：在合规测试用户中定义激活、任务完成率、人工接管率和满意度，形成一份含样本量、周期、口径和失败案例的复盘。
3. **英文沟通**：完成真实可验证的英文项目介绍、产品 Demo 和邮件写作训练；在达到工作语言水平前，不在简历中写“英语流利”。

## 三分钟面试演示顺序

1. 用首页说明养老业务问题和角色边界；
2. 让 Agent 查询真实服务并生成带证据的结构化照护建议；
3. 发起预约，展示人工确认、幂等执行和审计；
4. 打开运营驾驶舱，解释成功率、延迟、Token、降级与失败类型；
5. 展示 WorkBuddy MCP 与 ima-ready 知识包，说明企业协作和知识治理；
6. 以“未部署商业客户、豆包需自有凭据、不可替代医疗判断”收尾，主动说明边界。
