# AI 解决方案销售演示 Playbook

## 演示对象

面向养老服务机构的信息化负责人、业务运营负责人或一线服务主管进行模拟方案演示。当前无真实客户、合同、订单或收入证据，因此所有客户场景和 ROI 均应标注“模拟”。

## 会前发现

- 目前活动、上门服务、助餐和健康信息分别由哪些系统或表格承载？
- 一线人员每天重复核对哪些字段，发生错误后如何追溯？
- 哪类动作必须经用户、家属或主管确认？
- 是否允许模型处理健康信息，数据保存和第三方模型调用的边界是什么？
- 项目验收更看重响应速度、人工节省、完成率还是合规性？

## 八分钟 Demo

1. 让 Agent 查询活动或服务，展示来自数据库的真实 ID。
2. 发起预约，故意少给一个字段，展示 Agent 追问而非猜测。
3. 信息齐全后展示 `PENDING` 确认卡，先取消一次证明不会写库。
4. 再执行一次并从业务订单和审计记录双向核验。
5. 询问专业规则，展示 ima-ready 同源知识的 `[KB:...]` 引用。
6. 上传一张非敏感演示图片，说明豆包配置状态、多模态路由和医疗不确定性。
7. 打开运行指标和 WorkBuddy MCP 工具，说明持续运营与扩展方式。

## 异议处理

| 异议 | 证据式回答 |
| --- | --- |
| “只是聊天机器人” | 展示工具调用、订单变化、确认状态机和审计记录 |
| “模型会乱说” | 业务成功以工具结果为准；无工具成功声明被二次校正 |
| “会不会越权” | JWT、当前用户所有权、一次性确认令牌；MCP 不含个人和写工具 |
| “知识会过期” | 文档含负责人、版本和复核日；过期或非 approved 内容不被检索 |
| “怎么证明价值” | 先定义基线和验收指标，再做小样本试运行；不提前承诺 ROI |

## 下一步方案

真实售前项目应输出需求确认单、数据字段清单、模型/数据处理边界、试点范围、验收指标、风险清单与回滚方案。本项目可展示方法和技术原型，但不能代替真实客户验收材料。
