# 哪些文档可以被引用

`ima-ready/` 保存本地 Agent 的知识来源和供 ima 手工导入的文件。按北京时间判断，只在 `reviewed_at ≤ 今天 ≤ next_review_at` 时使用 `approved` 文档。到期日当天有效，次日即使内容仍在缓存中也会被排除。`governance` 供维护者查阅，`draft` 供编辑或隔离，两者都不进入运行时检索或 ima 导入清单。

# 如何复核和发布

1. 保留稳定的 `document_id`，填写负责人、版本、状态、审核日期、下次审核日期、适用范围等元数据。新增或重命名文件时同步更新 `knowledge-base/manifest.json` 的文件清单。
2. 逐项复核正文。技术能力须能定位到具体版本的实现或测试；演示流程写明账号权限与数据条件；模拟客户与收益注明假设。来源失效、相互冲突或有待确认的内容先转为 `draft`。真实养老流程、健康、隐私或合规判断须由相应专业人员复核。案例使用虚构数据，知识文件中禁止存放凭据、联系方式和个人病历。
3. 在文档中记录本次实际核对的来源、修改和适用范围，完成复核后更新版本及日期。`owner` 标识后续维护责任人；签审情况以实际记录为准。
4. 从仓库根目录运行 `.\scripts\validate-knowledge-base.ps1`。检查通过后，在运行环境查看 `/chat/status` 的知识状态，通过知识检索用例核对来源。结构校验遇到已过期的 `approved` 或 `governance` 会失败。已隔离的 `draft` 可以保留真实的历史日期，并产生待复核警告。

# ima 导入与下线

在有权限的 ima 资料库中移除旧版或已隔离的副本，仅导入当前审核有效的 `approved` 文件。在 WorkBuddy 绑定资料库后，用具代表性的问题核对新来源，再检查撤下的资料已无法检索，记录资料库、文档 ID、版本和操作日期。仓库修订后，外部副本仍须在对应账户中单独验收。
