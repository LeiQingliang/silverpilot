# 诚信前提

本文是产品演示和售前演练手册，不是真实客户成交记录。禁止将模拟练习写成签约、收入、回款、复购或客户上线。

# 需求发现

1. 当前服务预约、活动报名和健康咨询分别由谁处理？
2. 用户通常在哪个步骤放弃，人工需重复核对哪些信息？
3. 哪些业务结果必须留痕，哪些操作必须人工批准？
4. 数据隔离、医疗安全、知识更新和故障追踪分别有什么验收要求？

# 八分钟演示链路

1. 用自然语言查询真实服务目录，展示 ID 与工具轨迹。
2. 请 Agent 发起一个预约，展示参数补全和二次确认，先选“不执行”证明可控。
3. 再完成一次确认，从业务订单和审计记录双向核验。
4. 检索知识库，展示 `[KB:...]` 来源和医疗边界。
5. 打开运营指标，说明怎样根据延迟、失败、工具成功率和待确认数迭代。

# 常见异议

- “这不就是聊天机器人吗？”——现场展示工具调用、真实订单、确认状态机与审计表。
- “模型乱说怎么办？”——业务成功以后端工具结果为准，无工具依据的成功声明会被护栏拦截。
- “数据安全吗？”——密钥仅在后端；个人查询校验 JWT 和所有权；MCP 只提供非个人只读能力。
- “怎么衡量价值？”——先建立基线，再核对任务完成率、人工转交率、平均处理时长和用户确认率；没有真实数据时不给 ROI 承诺。
