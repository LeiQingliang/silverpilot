# Railway 数据库配置

状态：部署准备文件，不是已经上线或通过云端验收的证明。

- 构建上下文：仓库根目录；Dockerfile：`deploy/railway/mysql.Dockerfile`。
- 服务名：`mysql`；仅私网 `mysql.railway.internal:3306`，不创建公共域名或 TCP Proxy。
- 必须为该服务单独挂载新持久卷至 `/var/lib/mysql`。不要复用未知来源或现有业务数据库卷。
- 固定 `MYSQL_DATABASE=a_old`、`MYSQL_USER=cecsms`。默认监听 `::`，需在 Railway 实际验证私网连接。
- 设置四个彼此不同的运行时秘密：`MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`SILVERPILOT_ADMIN_PASSWORD`、`SILVERPILOT_VISITOR_PASSWORD`。使用密码生成器生成 32–72 位随机 ASCII 字符，仅包含字母、数字、`_`、`-`；建议分别生成 48 位随机十六进制字符串。不要放入构建参数、Git、截图或日志。
- 首次初始化导入仓库合成数据。导入前全部 18 个种子账号的密码均改为 `NULL`，随后仅为 `admin`（管理员）和 `linge`（普通用户）设置 bcrypt cost 12 密码。管理员密码仅交给所有者；其他种子账号保持不可登录。`linge` 仍拥有原普通用户业务权限，不是只读访客；如果公开共享该账号，所有访客会共享其业务数据与操作状态。
- 原 SQL 和本地 Compose 不变。哈希工具读取标准输入，数据库不保存明文应用密码。
- 只有完整初始化成功才写入卷内 `.silverpilot-railway-initialized-v1` 标记。已有 MySQL 数据但没有此标记时，容器拒绝启动，防止自动重启把中断的初始化当作正常数据库。不要手工补写标记绕过检查；应先检查备份与卷中状态，再选择经确认的恢复方案。
- 配置无效时，在创建数据库前拒绝运行；导入中断时会保留卷供检查，不自动删除数据或重置已有账号。
- 成功后的重启/重新部署不再导入、锁定或修改账号。修改以上环境变量不会轮换已存在数据库中的密码，轮换需通过经授权的数据库/应用流程执行。
- `httpd-tools` 仅提供 `htpasswd` bcrypt 工具，镜像没有启动 HTTP 服务。基线沿用 `database/Dockerfile`，将来升级基础镜像及包版本时应同步复核这两份构建文件。

发布验证至少覆盖：首次导入、18 个账号默认密码全部失效、两个新密码可用、数据库外网不可达、重新部署保留数据/密码、错误凭据在初始化前被拒绝、模拟中断后缺失完成标记的卷拒绝启动，以及卷备份与恢复。
